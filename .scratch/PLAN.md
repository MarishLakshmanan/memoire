# Phase plan

The build order adopted while grilling `plan.md`, refined from that file's original
"Moving forward" section (kept there as historical record, not updated). This is the
current source of truth for phasing.

Prompts are deliberately late: they're cheap to write and only worth tuning once real
Notes exist to test them against.

## 0 — Auth spike — done

FastAPI + MCP over streamable HTTP + Clerk, one throwaway `ping` tool. Proves the riskiest,
least-documented part (Clerk has no Python MCP guide) before any domain code depends on it.
See `.scratch/phase-0-auth-spike/spec.md`.

## 1 — DB layer — done

Postgres schema for Notebook and Note (SQLModel + Alembic), verified against a real running
database, not just autogenerated. See `.scratch/phase-1-db-layer/spec.md`.

## 2 — Tools — done

`save_note`, `retrieve`, `list_notebooks`, `search_notes`, plus the ownership-enforcing query
layer deferred from phase 1. Verified through the real MCP protocol and a dedicated
cross-tenant isolation test. See `.scratch/phase-2-tools/spec.md`.

## 3 — Prompts — done

`save_session`, `summarize_notebook`, `recall`, `how_to`, plus `get_notebook_contents` /
`save_notebook_summary` for the Root Summarizer flow. Verified the Q14 staleness-delta
property end to end. See `.scratch/phase-3-prompts/spec.md`.

## 4 — Frontend + delete — not started

React + Vite + Tailwind v4, Clerk for login/signup, mockups at `assets/mockup/`. Delete lives
only here per ADR-0003 — the MCP server has no delete tool.

## Open cross-phase items

Real Clerk + Claude Code end-to-end test, covering all six tools and four prompts — not yet
done for anything past the `ping` tool tested in phase 0. Filed as
`.scratch/phase-2-tools/issues/01` and `.scratch/phase-3-prompts/issues/01`.
